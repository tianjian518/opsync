# opsync

通过 **OpenList（AList v3 兼容）** 把网盘 A 里的东西**定时搬运**到网盘 B 的极简工具，带一个**浏览器管理界面**。

设计取舍（只做核心功能，没有花哨东西）：

- 支持**多个 OpenList 账号**：顶部标签页，每个账号一个子页面，可随时添加/切换/删除
- 每个账号的登录信息**持久化**到 `/data/config.toml`（抱脸等平台的持久化目录），刷新页面不丢失
- **同实例**（源/目标在同一个 OpenList）= 走服务端 `/api/fs/copy` 或 `/api/fs/move`，不占本地带宽
- 递归遍历源目录、自动建目录、按「文件名 + 大小」跳过已同步的文件
- **支持按文件大小范围搬运**：只搬 5GB 以下的、只搬 1GB~10GB 的、只搬大于 1GB 的……范围外的文件留在源目录不动
- 两条模式：`copy`（保留源）/ `move`（搬完删源，可选清理空目录）
- 极简调度：`interval`（每 N 分钟）/ `daily`（每天几点）/ `once`（仅手动）
- 各账号的搬运任务由全局线程池**并发执行**，互不影响
- 依赖：`requests` + `flask`

> 一个轻量的网盘定时搬运工具：填连接、浏览选目录、建多条路线、看日志，全在网页里完成。

## 安装

```bash
pip install -r requirements.txt
```

需要 Python 3.11+（用到内置 `tomllib` 解析配置）。

## 使用（全在网页里）

```bash
python main.py                 # 起 Web 管理界面（监听 $PORT，默认 7860）
```

浏览器打开 `http://<host>:<PORT>`，按这个顺序操作：

1. 点左侧 **+ 添加账号**，填展示名 + OpenList 地址 + 账号 + 密码。
2. 在 **连接设置** 里点 **保存连接**（登录信息立即落盘，刷新不丢）；再点 **保存并连接测试**（连不通不允许建路线）。
3. 测试通过后，回到 **搬运路线** 点 **+ 添加路线**：点「浏览选择」在目录树里点出**源目录**和**目标目录**（不用手敲路径），再选**搬运文件大小范围**（见下）、模式与调度、是否启用。
4. 点 **保存路线**后调度器按各自设置自动跑；也可单条「运行」或「立即运行全部」手动触发。
5. 可添加多个账号，每个账号独立运行；左侧 **日志** 实时显示进度，**运行结果** 汇总每条路线最近一次执行的情况。

配置保存在 `/data/config.toml`（持久化目录，重启不丢）；本地没 `/data` 时落在 `config.toml`。

## 界面结构

界面采用**左侧边栏 + 右侧内容区**，功能按类分到不同菜单，避免所有东西挤在一屏：

| 侧栏位置 | 菜单 | 作用 |
|---------|------|------|
| 账号 | 每个账号一项 | 点击切换当前操作的账号；左侧圆点绿=已通过连接测试，橙点=正在运行 |
| 功能 | 搬运路线 | 该账号的路线列表、新建/编辑/运行/终止 |
| 功能 | 连接设置 | OpenList 地址与账号密码、连接测试、删除账号 |
| 功能 | 运行结果 | 所有账号每条路线最近一次的结果（成功/失败/已终止 + 各项计数） |
| 功能 | 日志 | 实时日志输出 |
| 功能 | 使用说明 | 操作指引 |

交互上的几点设计：

- **账号与功能分离**：切账号时保持当前所在的功能页（在「运行结果」切账号不会被弹走）
- **路线卡片可折叠**：默认收起只显示一行摘要（名称、源→目标、启用/模式徽章、运行状态、按钮），点标题展开编辑；展开状态在切菜单后仍保留
- **「已启用 / 已停用」「copy / move」直接标在卡片上**，不用点开就能看清每条路线在干什么
- 新建路线会**自动展开并聚焦名称**，改名称/模式时卡片摘要**实时同步**
- 窄屏（≤820px）时侧栏自动收成顶部横向条，手机上也能用

## 强制终止正在运行的路线

路线跑起来之后（不管来自「运行」「立即运行全部」还是调度器自动触发），
页面上会实时反映运行状态：

- 左侧栏该账号出现**橙点**，底部显示运行中条数
- 路线卡片出现 **运行中** 徽章、左边框变橙色，该条的「运行」按钮变灰为「运行中…」并禁用
- 同时**出现「终止」按钮**（平时隐藏）

点「终止」即可停住这条路线；也可用列表上方的 **「终止全部」** 一次停掉该账号下所有在跑的路线。

**终止的语义（重要）**

采用**协作式取消**，只在安全点中断：

- ✅ 正在进行的**单个**复制/移动请求会跑完 —— 不会留下半截搬运，也不会误删
- ✅ 之后**不再发起新动作**：没轮到的子目录/文件保持原样，直接停止
- ✅ 已完成的部分**如实保留**并在统计里体现（「已搬 N」），终止**不计入「失败」**
- ✅ 可随时再点「运行」继续搬（已搬过的会自动跳过）

等待网络响应时也能**立刻**中断：请求在后台线程发出，主线程监听取消信号，
所以点「终止」不用等满 HTTP 超时（实测 1 秒内退出，`timeout` 设的是 120 秒）。

状态里会标记 `cancelled`，界面显示「已终止」。

> 注意：调度器会按各路线自己的 `interval_minutes` / `run_at` 继续安排下次运行。
> 「终止」只停当前这一次；想彻底不再自动跑，把该路线的「启用」勾掉或改成 `once`。

## 搬运文件大小范围

每条路线可单独设置大小筛选，网页里是下拉框，内置这些常用档位：

| 档位 | 效果 |
|------|------|
| 全部（不限制） | 默认，源目录里的文件全搬，行为与旧版一致 |
| 小于 5GB / 1GB / 500MB | 只搬不超过该大小的文件 |
| 大于 1GB / 5GB | 只搬不小于该大小的文件 |
| 1GB ~ 10GB、5GB ~ 50GB | 只搬区间内的文件 |
| 自定义… | 手填，支持 `500MB~5GB`、`小于5GB`、`大于1GB`、`>5GB` 等写法 |

**重要行为说明**

- 筛选粒度是**单个文件**，不按目录总大小判断；目录本身始终会照常创建。
- 范围外的文件**留在源目录不动**：`copy` 不复制，`move` 也**不搬、更不删**。
  所以开这个功能不会让你丢东西，下次把范围放宽还能接着搬。
- 开了 `delete_empty_dirs` 时，如果源目录里还有因超范围而留下的文件，该目录**不会被删**。
- 统计里的「超出范围」= 本次因大小不符合而被跳过的文件数。

单位写法：`250B` 是 250 字节，`5GB` 是 5×1024³ 字节，`1.5g` / `1KiB` 也都认；
**只填一个裸数字（如 `1024`）按 MB 算**。

命令行（本地调试用）：

```bash
python main.py --check         # 仅测试各账号连接并列出根目录
python main.py --once          # 立即执行所有已配置账号的启用路线一次
python main.py --config x.toml # 指定配置文件
```

## 配置示例（config.toml）

```toml
[[openlists]]
id = "conn-1"
name = "账号1"
url = "https://a.hf.space"
username = "admin"
password = "密码"
tested_ok = true

  [[openlists.routes]]
  name = "照片备份"
  src_path = "/阿里云盘/照片"
  dst_path = "/OneDrive/备份/照片"
  mode = "copy"
  enabled = true
  overwrite = false
  delete_empty_dirs = false
  schedule_type = "interval"
  interval_minutes = 30
  run_at = "03:00"
  min_size = ""              # 大小下限，带单位（"1GB"）；留空 = 不限
  max_size = "5GB"           # 大小上限，带单位（"5GB"）；留空 = 不限

[[openlists]]
id = "conn-2"
name = "账号2"
url = "https://b.hf.space"
username = "admin"
password = "密码"
tested_ok = true

  [[openlists.routes]]
  name = "文档同步"
  src_path = "/115/文档"
  dst_path = "/天翼云/文档"
  mode = "move"
  enabled = true
```

也可通过环境变量覆盖**第一个**账号的连接（`OPSYNC_URL` / `OPSYNC_USERNAME` / `OPSYNC_PASSWORD`，优先级高于网页保存的配置）。路线建议在网页里建。

## 本地自测

```bash
python -m unittest test_sync -v
```

用内存假客户端验证递归遍历、跳过判断、copy/move 行为、**大小范围筛选**，不依赖真实 OpenList。

## 文件结构

| 文件 | 作用 |
|------|------|
| `openlist_client.py` | OpenList/AList v3 API 客户端（登录、列目录、复制/移动、下载上传、删除） |
| `sync.py` | 搬运引擎：`SyncEngine` 单连接、按路线 `run_route` 递归遍历 |
| `web.py` | Web 管理界面（多账号子页面 + 目录浏览器）+ 后台并发调度器 |
| `confighelper.py` | 配置加载/序列化（多账号模型 + 递归 TOML 写入）/保存路径 |
| `main.py` | 命令行入口，默认起 Web |
| `config.toml` | 配置示例 |
| `test_sync.py` | 逻辑自测（`python -m unittest test_sync`） |


## 说明

- 接口路径/字段严格对齐 AList v3 / OpenList 官方文档（`/api/fs/list`、`/api/fs/get`、
  `/api/fs/put`、`/api/fs/copy`、`/api/fs/move`、`/api/fs/mkdir`、`/api/fs/remove`、
  `/api/auth/login`）。
- 跨实例下载会自动处理 302 跳转，且**不会把你的 token 发给第三方域名**。
- 网盘路径以 OpenList 里显示的虚拟路径为准（一般形如 `/挂载名/子目录`）。
